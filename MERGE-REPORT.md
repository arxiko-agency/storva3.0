# STORVA merge report (2026-11-21)

## What this package is
One TanStack Start + Supabase project:
- **Design** = `storva-auth-bridge-main.zip` (public pages, login, reset password, dashboard frame, styles).
- **Backend / business features** = `storva-lovable/` from `STORVA-FINAL-FIXED-1.zip` (Supabase schema + migrations, server functions, billing/Razorpay, plans and limits, products, orders, customers, store designer, analytics, WhatsApp, notifications, AI studio, public storefront, webhooks).
- `legacy/` keeps everything else from the original ZIP untouched: `STORVA-express/` (Node/Express/MongoDB app), notes, audits, archived landing pages. **It is not wired into the app** (see "Open decisions").

## Open decisions
- **Express/MongoDB app (`legacy/STORVA-express`)**: it is a second, independent backend with its own users, plans and products in MongoDB. It cannot share logins or data with the Supabase app. If that is your production system, the design has to be integrated with it separately (static React build served by Express + its REST API). That was not done silently; tell me which backend is your live one.
- Plan names: the database defines Free / Starter / Pro / Enterprise (limits 10 / 100 / 1,000 / unlimited products). If you expect "Growth", rename it in `plans`.
